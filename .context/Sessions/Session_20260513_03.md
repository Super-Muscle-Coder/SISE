## Friction Points Encountered

### Issue 1: Docker Multi-Stage Build Casing & PyTorch CPU Optimization
- **Problem**: Initial Dockerfile had `FROM ... as builder` (lowercase), causing build warnings. PyTorch CUDA dependencies bloated image to 5GB+ with slow build times.
- **Resolution**: Fixed casing to `FROM ... AS builder`, replaced CUDA with CPU-only PyTorch via `--extra-index-url https://download.pytorch.org/whl/cpu`. Result: 2.13GB image, 3-4 min build time (70% faster).

### Issue 2: Uvicorn FastAPI Factory Pattern & Entrypoint Compatibility
- **Problem**: Bash entrypoint scripts not portable across Windows/Linux environments; uvicorn didn't recognize factory pattern initially.
- **Resolution**: Rewrote entrypoint.py in pure Python, added `--factory` flag to uvicorn command, dependency checks for fastapi/torch/open_clip.

### Issue 3: ENV Variable Defaults & Model Cache Directory
- **Problem**: Missing ENV defaults caused startup crash; model cache directory permissions conflicted with non-root user.
- **Resolution**: Added ENV defaults (AI_SERVICE_PORT, CLIP_MODEL_NAME, DEVICE, MODEL_CACHE_DIR) in Dockerfile, pre-created cache directory with proper permissions.
